# Tyrus for IntelliJ / WebStorm

Applies to every JetBrains IDE (IntelliJ IDEA, **WebStorm**, PyCharm, ...), since they share the same platform.

You can use tyrus **today** via [LSP4IJ](https://github.com/redhat-developer/lsp4ij), no plugin to build. A bundled native plugin is deferred until there is demand (see `__roadmap__/implemented-editors-plan.md`); the LSP4IJ path already gives the full feature set.

Do **not** reimplement a lexer/parser/checker for IntelliJ. The tyrus compiler exposes everything through the `tyrus lsp` language server; the IDE consumes it, exactly like the VS Code, Neovim, and Zed integrations.

## Installation

### Prerequisites

1. From the repo root run `./scripts/tyrus` so `tyrus` is on your `PATH`.
2. Run `./scripts/editors` to regenerate the TextMate grammar and other editor artifacts.

### Step 1, Install the LSP4IJ plugin

Settings → **Plugins** → **Marketplace** → search **LSP4IJ** → Install.

### Step 2, Register the TextMate grammar (syntax highlighting)

1. Settings → **Editor** → **TextMate Bundles**.
2. Click the **+** button and select the VS Code extension directory:
   ```
   /path/to/tyrus/editors/vscode
   ```
   WebStorm recognizes VS Code extensions with a `package.json` as TextMate bundles.
3. Settings → **Languages & Frameworks** → **Language Servers** → select the `tyrus` server.
4. In the **Language** column, select **TextMate**.
5. In the **Language ID** column, type `*.tyr`.
6. Restart WebStorm.

### Step 3, Register the Language Server (diagnostics, hover, completion)

1. Settings → **Languages & Frameworks** → **Language Servers** → click **+** (New Language Server).
2. Configure:
   - **Name:** `tyrus`
   - **Command:** `tyrus lsp`
   - **Working Directory:** `$ProjectFileDir$` (resolves to the current project root)
3. In the **Server Environment Variables** field, add:
   ```
   PATH=/home/your-user/.cargo/bin:$PATH
   ```
   This ensures the LSP4IJ process can find the `tyrus` binary.
4. In the **Mappings** tab, add:
   - **File name patterns:** `*.tyr`
5. Apply and close.

### Step 4, Verify

Open `src/main.tyr` from a project created with `tyrus new`. Check:

- **Syntax highlighting**, keywords, types, strings, and comments are colored.
- **Diagnostics**, type errors, borrow errors, and unknown identifiers appear as you type.
- **Hover**, place the cursor over an identifier to see its type.
- **Completion**, press `Ctrl+Space` for local and exported symbols.
- **Go to definition**, `Ctrl+Click` or `Ctrl+B` on a symbol.
- **Find references**, `Alt+F7` on a symbol.
- **Rename**, `Shift+F6` on a symbol.
- **Signature help**, parameter names appear while filling in a function call.
- **Quick Fix**, press `Alt+Enter` on a diagnostic and choose a deterministic compiler or linter action.

If diagnostics and hover do not appear, open **View → Tool Windows → Language Server Protocol** to verify that `tyrus lsp` is running without errors.

## A future native plugin (deferred)

A minimal plugin would register the `tyrus` file type (`*.tyr`) and start `tyrus lsp` (project root = the directory with `tyrus.json`), relying on the server for all intelligence. Two wiring options: the **LSP4IJ** API (works on Community) or IntelliJ's **native LSP API** (paid IDEs). It is a separate Kotlin/Gradle project (needs the IntelliJ Platform SDK), which is why it is deferred.

## What is intentionally out of scope

- A hand-written PSI/parser or type checker (the compiler is the single source of truth).
- A TextMate/Tree-sitter grammar copy, keyword lists are generated by `cargo run -p xtask`; an IntelliJ target can be added to that generator if native highlighting is ever needed.
