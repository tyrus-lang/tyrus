# tree-sitter-tyrus

Tree-sitter grammar for **tyrus**, used by editors that highlight through tree-sitter (Zed, Neovim's nvim-treesitter, Helix, ...). Semantic detail (types, ownership, diagnostics) still comes from the `tyrus` language server; this grammar only describes structure for highlighting and folding.

## Layout

- `grammar.js`, the grammar (source of truth; hand-written).
- `src/`, the generated parser (`tree-sitter generate`), committed so consumers can build without the CLI.
- `src/scanner.c`, the one hand-written file under `src/`: an external scanner that decides what a `?` is. The `?` that propagates a failure, the `?` of an optional arrow parameter and the `?` of a fallible `as T?` cast are all spelled like the ternary's, and telling them apart needs lookahead past the `?` (`f(x)? - 1` against `c ? -1 : 2`). The rules are at the top of the file. It is plain C with no library calls, so it also builds for editors that load the grammar as WebAssembly.
- `queries/highlights.scm`, the highlight query. **Generated** by `cargo run -p xtask` from `tyrus_core::keywords`, so keyword and reserved-word lists stay in one place; do not edit it by hand.

## Regenerate after editing `grammar.js`

```bash
cd editors/tree-sitter-tyrus
npx tree-sitter generate
```

The grammar is validated against its in-repository corpus by `scripts/tree-sitter`. To run that corpus directly from this directory:

```bash
npx tree-sitter test
```

## Notes

- The `tree-sitter` CLI caches the compiled parser by language name, not by path, so two checkouts of this grammar (another branch, a worktree, a copy) share one cached `tyrus` library, and a checkout whose `src/parser.c` is older than the cache silently runs the other checkout's parser. `scripts/tree-sitter` is safe because it regenerates `src/parser.c` first; for manual comparisons between checkouts, give each its own `TREE_SITTER_LIBDIR`.
- Generic calls (`identity<i32>(42)`) parse as comparison expressions rather than a dedicated call-with-type-arguments node; this keeps `a < b` unambiguous and does not affect highlighting.
- The keyword/reserved lists in `queries/highlights.scm` are regenerated by the workspace `xtask`; the parser itself must be regenerated with `tree-sitter generate` when `grammar.js` changes.
